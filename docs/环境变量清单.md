# LOOP 环境变量清单

> 目标：新沙盒只需设置 ≤5 个变量即可开工；其余均可推导或有安全默认值。
> 完整清单用于排查与审计，不必全部手写。

## 最小启动集（≤5 个）

在 Trae/CI 沙盒里，真正必须由人提供的只有：

| 变量 | 必填 | 示例 | 说明 |
|---|---|---|---|
| `GH_TOKEN` | 是 | `ghp_xxx` | GitHub 个人访问令牌或 `GITHUB_TOKEN`。`gh`/`git` 操作都走它。 |
| `LOOP_ORG` | 否* | `Cloudbird-Software` | 默认从 `GITHUB_REPOSITORY_OWNER` 推导。Trae 沙盒需显式填。 |
| `LOOP_REPO` | 否* | `product-x` | 默认从 `GITHUB_REPOSITORY` 推导。loop 控制面作业填 `loop`。 |
| `LOOP_WS` | 否* | `/work/product-x` | 工作区路径；默认等于 `LOOP_ROOT`。impl 沙盒需指向产品仓 clone。 |
| `LOOP_ROLE` | 否 | `impl` | 当前会话角色：`impl` / `verify` / `planner` / `auditor` / `ops`。默认 `impl`。 |

> *在 GitHub Actions 中， `GITHUB_REPOSITORY_OWNER` / `GITHUB_REPOSITORY` / `GITHUB_WORKSPACE` 会自动注入，
> 因此 Actions 环境下最小集只有 `GH_TOKEN`（Actions 里即 `secrets.GITHUB_TOKEN`）。

## 沙盒身份与路径

| 变量 | 默认值 | 由谁提供 | 影响面 |
|---|---|---|---|
| `LOOP_ROOT` | `/workspace`（本地）/ `/work`（Trae） | Trae 槽位或 Actions | 控制面代码根目录；`loopd` 从这里找 `lenses/`、`gates/` 等。 |
| `LOOP_WS` | `$LOOP_ROOT` | Trae 槽位 | impl 实际工作区，通常指向 clone 的产品仓。 |
| `LOOP_SANDBOX_ID` | `local-<uuid>` | Trae 槽位或自动生成 | 沙盒唯一标识，写入 issue 块用于排查。 |
| `LOOP_MODEL` | `unknown` | Trae 槽位 | 当前 AI 模型名，用于异构校验与路由日志。 |

## 调度与租约

| 变量 | 默认值 | 说明 |
|---|---|---|
| `LOOP_MAX_CARDS_PER_SESSION` | `1` | 单会话最多领卡数，达到则 `RETIRE`。 |
| `LOOP_NEXT_BLOCK_SEC` | `60` | `loop next` 阻塞等待 ready 卡的最长时间（秒）。 |
| `LOOP_LEASE_MIN` | `30` | 卡租约时长（分钟），超时无心跳视为僵尸。 |
| `LOOP_HEARTBEAT_SEC` | `120` | 心跳守护进程睡眠间隔。 |
| `LOOP_AUTOSAVE_SEC` | `300` | 自动落盘守护进程睡眠间隔。 |
| `LOOP_REAPER_SEC` | `60` | 僵尸卡回收线程睡眠间隔。 |
| `LOOP_BRANCH_PREFIX` | `loop/card` | `loop save` 创建的分支前缀。 |

## CI / 门禁 / 审计

| 变量 | 默认值 | 说明 |
|---|---|---|
| `LOOP_CI_BASE` | `HEAD~1` | gate diff 的 base commit；PR 中由 `GITHUB_BASE_REF` 覆盖。 |
| `LOOP_CI_REF` | `""` | gate_paths 读取的 ref；默认用 `GITHUB_REF`。 |
| `LOOP_POLICY` | `policy.yml` | conductor/tick 读取的策略文件路径。 |
| `LOOP_POLICY_PATH` | `../policy.yml` | `seam_a/router.py` 读取的 policy 路径。 |
| `COMMAND_AUTHORS` | `""` | `conductor/commands.py` 微指令白名单，逗号分隔 GitHub login。 |

## Bootstrap 与版本校验（仅在 `loopd/bootstrap.sh` 首次部署沙盒时使用）

| 变量 | 必填 | 说明 |
|---|---|---|
| `LOOP_BOOTSTRAP_REF` | 否 | 默认 `v0.1.0`；要拉的 loop tag/branch。 |
| `LOOP_BOOTSTRAP_SHA256` | 是* | `bootstrap.sh` 的期望 sha256；不匹配则 `SHA_MISMATCH` 退出。 |
| `LOOP_PROMPTS_SHA` | 否 | prompts 目录的期望 git tree SHA；未填不校验。 |
| `OPENCODE_VERSION` | 否 | 默认 `v1.18.4`；opencode 执行体版本。 |
| `OPENCODE_SHA256` | 否 | opencode-linux-x64.tar.gz 的期望 sha256。 |

> *`LOOP_BOOTSTRAP_SHA256` 是安全敏感变量，应放进 Trae 敏感变量槽位。

## 跨仓 / 人工触点

| 变量 | 默认值 | 说明 |
|---|---|---|
| `LOOP_PRODUCT` | 无 | `scribe.yml` / `canary-chain.sh` 操作的目标产品仓名。 |
| `LOOP_HUMAN` | 无 | Incident 通知时 `@` 的人类负责人 GitHub login。 |

## 凭证类 Secret（不在环境变量里硬编码）

这些只在 GitHub Actions / Trae 敏感槽位里出现，**禁止写进任何文件或日志**：

- `GH_TOKEN` / `GITHUB_TOKEN`
- `COPILOT_GITHUB_TOKEN`（强模型验收，开发期间暂不启用）
- `LLM_GATEWAY_KEY`（promptfoo / seam A 最强模型）
- `LOOP_CANARY_TOKEN`（canary 跨仓操作 product-x）
- `SCRIBE_GH_TOKEN`（journal 镜像）
- `POLICY_R_APP_ID` / `POLICY_R_APP_KEY`（drift 读 ruleset）
- `POLICY_W_APP_ID` / `POLICY_W_APP_KEY`（policy apply，当前被 CHARTER N5 禁用）

## 已废弃 / 非 loopd 直接使用的变量

| 变量 | 状态 | 说明 |
|---|---|---|
| `LOOP_IO_MODE` | 废弃 | 旧 relay/file 模式已在 #52/#53 移除；`loopd` 只通过 CLI 接收指令。 |
| `LOOP_POLL_MS` | 废弃 | 旧 shim 轮询间隔；新 `loopd` 使用阻塞 + 事件循环。 |
| `LOOP_TIMEOUT` | 废弃 | 旧 shim 命令超时；新 `loopd` 命令默认 1800 秒，可在代码中改。 |

## 最小 Trae 沙盒配置示例

```bash
# 普通环境变量
LOOP_ORG=Cloudbird-Software
LOOP_REPO=product-x
LOOP_WS=/work/product-x
LOOP_ROLE=impl
LOOP_SANDBOX_ID=impl-1
LOOP_MODEL=kimi-k2.7

# 敏感变量
GH_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxx
LOOP_BOOTSTRAP_SHA256=601eeffc986529cbe024e4426beab3031fdb20db7c4e463535dcd248362ac260
```

对应的开场白：直接粘贴 [`prompts/P0.md`](../prompts/P0.md) 全文。
