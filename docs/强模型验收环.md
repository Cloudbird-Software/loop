# 强模型验收环（review 环）架构

> 定稿 @2026-07-30。本文件是本轮讨论的架构结论存档，是 WAVE-12 全部卡片的规格来源。
> 相关 ADR：DECISIONS.md ADR-004 / ADR-005 / ADR-006。

---

## 0. 一句话

强模型验收 = **接缝 A 的一条新路由** + **接缝 B 的一个新执行体**；
其唯一合法产物是 **schema 化的可证伪断言（claim）**；
claim 必须走既有的**首次发现协议**做**异构复现**，确认后**固化为确定性 checker**；
提出 claim 的模型的**精度被持续记分**并回填路由。

---

## 1. 为什么它必须存在，以及它必须被约束成什么样

人类的原始诉求有两层，缺一不可：

1. **能自动化**：GitHub Copilot CLI 有正式的非交互模式（`copilot -p "<prompt>" --no-tty
   --allow-tool='shell(...)' --deny-tool='...'`，鉴权走 `COPILOT_GITHUB_TOKEN` /
   `GITHUB_TOKEN` 环境变量），并有官方 `github/copilot-cli` Action。
   所以"强模型验收"完全可以做成一个由 schedule / PR / `repository_dispatch` 触发的 workflow，零人工。
2. **但不可轻信**："我并不会直接推定某个模型说的一定是真的。"

第 2 层是硬约束，它决定了第 1 层的实现形态。因此本环的设计红线是：

> **强模型验收的输出，绝不能是 PASS/FAIL，也绝不能是散文。**
> 它只有一种合法产物——可证伪断言（claim），schema 化后由确定性程序拒收不合格项。

这与仓库里既有的 `finding.json`"无 evidence 一律非零退出"是同一套做法，只是把要求提高了一档：
finding 要求"有证据"，claim 额外要求"**有可粘贴执行的复现命令**"和"**有 falsifier**"。

## 2. 不把它写死成 Copilot 的理由

loop 已经有现成的抽象位，硬编码会破坏它：

| 位置 | 归属 | 做法 |
|---|---|---|
| 模型选型 | **接缝 A** | `ROUTING.yaml` 新增 `domain: review` 路由，模型可换 |
| CLI/执行体 | **接缝 B** | `UPSTREAM.yaml` 新增条目，`kind: cli`、钉版本、`official_source_only`、带 `degrade_path` |
| 配额与开关 | 方向盘 | `policy.yml` 新增 `review:` 段 |

`degrade_path` 写明：Copilot CLI 不可用时退回 `opencode` / `codex` headless + 接缝 A 路由出的强模型。
未登记进 `UPSTREAM.yaml` 的依赖会被 `gate/upstream-registered` 拦下——**这条铁律不为 Copilot 破例**。

同时需要更新既有结论：OPC-v4 §"Copilot 先不买"的判断在"CLI 可编程调度"这一事实下失效。
新结论见 ADR-004：Copilot CLI 仅作为**接缝 B 的一个可替换执行体**用于评审场景，
按 premium request 计费，配额写进 `policy.yml`。

## 3. claim 的形态（`.loop/schemas/claim.json`）

每条 claim 必填：

- `id` / `claim`（一句话；沿用 P-continue §7 的 evidence 红线，禁止"我觉得/可能/似乎"等主观措辞，校验器逐词拒收）
- `repro`：`cmd`（可粘贴执行）+ `expected` + `actual` + `env`（commit SHA / OS / 工具版本）
- `predicted_observation`：第三方在什么位置能观察到什么
- `falsifier`：出现什么输出就算这条断言被推翻
- `severity` / `confidence` / `reviewer_model` / `suggested_checker`

**没有可执行 `repro` 或没有 `falsifier` 的断言 → schema gate 直接丢弃，不进队列。**

这一条就把"强模型说的话"从"权威"降级成"待检验的输入"。

## 4. 复现管道：复用已有的首次发现协议

`cards/WORKFLOW.md` §4/§5 与 `prompts/P-continue.md` §7/§8 的首次发现协议，
本质就是"任何断言必须被独立复现才能进入修复"。强模型验收只是给这条管道换了个上游入口：

```
强模型评审 → claims(JSON, 过 schema gate) → 物化成 F 卡
                                            (origin: strong-model-review, status: unconfirmed)
  → 复现沙盒接单（异构：复现模型 ≠ 提出模型，用 LOOP_MODEL + CAS 强制，与 verify 同一机制）
      → 只跑 repro.cmd，不许自由发挥，三态输出：
          REPRODUCED      → 建修复 C 卡（depends_on 原卡）并**立即修**（§8 已规定"不许只建卡就走"）
          NOT_REPRODUCED  → 不改状态，评论客观差异，等下一个 AI，凑 ≥3 样本仲裁（§5 已规定）
          INCONCLUSIVE    → 收敛不了则升级为环境差异调查
```

判定 schema 见 `.loop/schemas/reproduction.json`。仲裁规则（由 conductor 计算 `next_action`，
复现沙盒不自行决定），直接沿用 WORKFLOW.md §5：

| 累计样本 | next_action |
|---|---|
| N 个 REPRODUCED + 0 个 NOT_REPRODUCED | `open_fix_card` |
| N 个 NOT_REPRODUCED + 0 个 REPRODUCED（N≥2） | `close_refuted` |
| 既有 REPRODUCED 又有 NOT_REPRODUCED，样本 <3 | `await_arbitration` |
| 样本 ≥3 仍不收敛 | `escalate_env_diff` |

## 5. 四条必须补的机制

### 5.1 角色阀门
`conductor/materialize.py` 的 `ROLE_CREATE_MAP` 新增 `reviewer` 角色：

- 评审模型**只有"提 claim"权**：token 只给 `issues: write`，不给 `contents: write`；
  CLI 侧用 `--deny-tool` 禁掉写文件 / 推分支。
- 复现沙盒**只有"判定 + 建修复卡"权**，不能改被评审的卡，也不能改被评审的代码。

### 5.2 复现器优先确定性（**本环最重要的一条**）
能写成脚本 / 测试的 `repro`，复现成功后**必须**固化为 `lenses/<name>.sh` 或一条回归测试——
直接复用既有的"occurrences ≥ 3 → 强制转『写检查器』卡"规则（阈值另由
`policy.yml` 的 `review.harden_after_confirms` 控制）。

它的意义：**让系统随时间把"某个模型说的"逐步替换成"确定性工具说的"，
使系统对模型的信任依赖单调下降。**

### 5.3 信任度量化
每条 claim 最终落到 `confirmed` / `refuted` / `inconclusive`，按 `reviewer_model` 聚合成
**claim precision** 与 **采纳率**，回填 `ROUTING.yaml` 中已经存在但全空的 `metrics` 段。
精度掉到阈值以下 → 自动降低该模型的评审权重或改路由。

"我不推定某个模型说的一定是真的"，在这里变成**一个被持续测量的数**，而不是一句原则。

### 5.4 防自证
claim 的复现沙盒**不能读 claim 的论证过程**，只能读 `repro` 字段。
这就是盲一半协议在 claim 层的复用。

## 6. 两条执行约束

- **成本**：Copilot CLI 在 Actions 里跑消耗 premium requests。
  强模型验收只挂在 standard/critical 卡与波次级验收上，trivial 不跑；日配额进 `policy.yml`。
- **非阻塞**：强模型验收**永远不做 required check**（模型不确定性不能卡合并线），它只产 claim。
  能卡合并的只有确定性 gate，以及被复现确认后固化出来的 checker。
  这与 `nightly-rubric.yml` 现有的"非阻塞、失败只开 Finding"定位一致。
  注意：非阻塞 ≠ 允许假绿——review workflow 自身失败时必须红（CHARTER N5）。

## 7. 对未来研究的兼容性承诺

架构承诺：**任何未来的效率新方法，都必须能表达成下面三者之一，否则不接。**

1. **新 lens / 新 checker（确定性）**：加 `lenses/<name>.sh` + `.md`，登记进 `shards.yml`，零 workflow 改动。
2. **新评审器 / 新角色（模型侧）**：`ROUTING.yaml` 加一条路由 + `prompts/PNN.md` +
   `UPSTREAM.yaml` 加一条执行体。
   因为**所有评审器都产同一个 claim schema**，下游（复现、修复、记分）一行都不用改——
   这是"可兼容未来研究"的技术保证点。
3. **新策略参数**：只改 `policy.yml`（它已经是"方向盘"文件），不改代码。

再加两条让它真正可研究：

- **统一漏斗 + 统一度量**：任何新方法的收益都必须体现为同一漏斗
  （claim → 复现 → 修复 → 固化为 checker）上的四指标变化
  （首次 CI 通过率 / reopen 次数 / avg diff 规模 / 单卡耗时成本）。
  `bench/replay/*.json` 的 holdout 重放包已经在了——新方法上线前必须在 holdout 上重放不劣化，
  走第 8 环升级环。**新方法和升级依赖走完全相同的准入门。**
- **实验维度**：`ROUTING.yaml` 新增 `experiment` 维度，按卡 id 哈希分流 arm A/B，
  指标按 arm 分组回填。这样"研究"变成常态化 A/B，而不是每次一次性大改。
  配合 prompts 按 SHA 引用 + UPSTREAM pin + policy 单文件旋钮，任何实验都能一条 revert 撤销。
