## 背景

用户要的效果：未来对云端 agent 说一句"继续"，agent 自己 gh 扫 repo、查 issue、找活干，不需要人安排。当前 [P0.md](../prompts/P0.md) 是工人 prompt（假设已在 loopd 沙盒内、开局 `loop next`），不是外部编排器入口。

## 要做什么

1. 在 `prompts/` 新建 `P-continue.md`，作为外部编排器入口提示词。
2. 路线抉择：选**路线 A**（轻）。理由：命令绕过已暂存、沙盒能直接跑 git/gh，让 agent 直接用 gh+git 干活，不依赖 loopd 当网关。loopd 的 CAS/租约保留给多沙盒并发（C-013），单 agent MVP 不需要。
3. 提示词结构：
   - **第 1 步 侦察**：`gh issue list -R product-x --label ready`、`gh issue list --label incident`、查未物化 wave、查 occurrences≥3 的 finding。
   - **第 2 步 判定**：按 OPC v4 第 8 部分排序选当前最高优先级活。
   - **第 3 步 切角色**：有 ready impl 卡→当 impl 领；有未物化 wave→当 planner；有堆积 finding→当 auditor；有 incident→当响应工。
   - **第 4 步 落地**：干活，完成后回 INDEX.md 改状态（暂行期）。
4. 提示词要可被任何云端 agent（如 Trae、Claude）加载即用，不绑死 loopd。

## 不要做什么

- 不要改 [P0.md](../prompts/P0.md)（那是工人 prompt，保留给 loopd 沙盒内使用）。
- 不要实现路线 B（loopd 内嵌多角色切换）——那是 C-013 之后的事。
- 不要假设 gh 已认证（本沙盒就未认证）。提示词里 gh 不可用时回退到读本地 cards/。
