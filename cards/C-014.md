## 背景

[F-001](./F-001.md) 复现确认：W2-002 的 /health impl（PR #50，已合并到 main 51bd2b5）用 `from flask import Flask, jsonify`，但 product-x 无任何依赖清单声明 Flask。干净环境（未装 Flask）下 `pytest tests/test_health.py` 收集期 ImportError，`python3 src/api/health.py` 端点无法启动。违反 P0.md「新增外部依赖前必须 loop upstream」。

本卡是 C-008（P4 闭环）的关键修复：不修则闭环 VERDICT 永远 FAIL，P4 终点不可达成。修完后 C-008 可重跑 verify → VERDICT=PASS → 闭环达成。

## 要做什么

1. 在 product-x 起分支 feat/c-014-health-stdlib。
2. 重写 `src/api/health.py`：仅用 `http.server` + `json`（stdlib）。保留 `GET /health` → 200 `{"status":"ok"}` 契约（对齐 [contracts/api-health.md](https://github.com/Cloudbird-Software/product-x/blob/main/contracts/api-health.md)）。
3. 重写 `tests/test_health.py`：不依赖 Flask；用 stdlib 起 HTTPServer（ephemeral port）+ urllib 发真实 GET /health 断言 200 + `{status:ok}`；并单测纯函数 `health_response()`。
4. 本地跑 `python3 -m pytest tests/test_health.py -v` + `bash .loop/verify.sh` 全绿。
5. commit + push + 开 PR。
6. 切 verify 角色重跑 V-008（在修复 commit 上）：VERDICT=PASS → 合并 → branch 推进。
7. 合并后回 C-008 评论闭环达成 + 耗时。

## 不要做什么

- 不要引入任何外部依赖（Flask/requests 等）。全 stdlib。
- 不要改 contracts/、.github/、tests/acceptance/、AGENTS.md（CODEOWNERS 占用 + 非本卡 paths）。
- 不要改 .loop/verify.sh（C-007 范围；退化态问题另立卡，不在本卡）。
- 不要在 verify PASS 前合并；不要在 commit 漂移时强行 PASS。
