## 背景

[F-002](./F-002.md) 复现确认：product-x 的 ci.yml `on:` 块只有 `pull_request` 和 `push`，缺 `merge_group` 触发器；而 branch ruleset（19949520）启用了 merge_queue（SQUASH/ALLGREEN）并要求 4 个 required_status_checks（lint/test/verify/contract）。后果：走 merge queue 的 PR 在临时分支 `gh-readonly-queue/main/pr-<n>-<sha>` 上 0 check-runs，entry 永久卡在 AWAITING_CHECKS。[C-014](./C-014.md) 合并 PR #53 时已被迫 break-glass（临时移除 merge_queue 规则→squash 合并→立即恢复）。本卡负责消除根因：给 ci.yml 的 `on:` 块补 `merge_group`。

## 要做什么

1. 在 product-x 起分支 fix/ci-merge-group。
2. 在 ci.yml 的 `on:` 块加 `merge_group: { branches: [main] }`（保留已有 pull_request/push）。
3. commit + push + 开 PR → 合并。
4. 验证走 merge queue 的 PR 队列临时分支上 4 个 check（lint/test/verify/contract）正常触发并全绿后自动合并，无需 break-glass。

## 不要做什么

- 不要动 ruleset 配置（[C-009](./C-009.md) 范围，已正确启用 merge_queue+ALLGREEN）。
- 不要改 ci.yml 的 jobs 内容（只加触发器）。
- 不要再 break-glass 移除 merge_queue 规则（本卡是修 ci.yml 根因，不是绕过 ruleset）。

## 验收

- ci.yml `on:` 块含 `merge_group: { branches: [main] }`。
- 走 merge queue 的 PR 不再卡 AWAITING_CHECKS（队列临时分支 CI 正常触发）。
